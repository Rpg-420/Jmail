# مستندات فارسی جی‌میل

## واژه‌نامهٔ مشترک

همهٔ مستندات فارسی این اصطلاح‌ها را به همین شکل به کار می‌برند. نامِ محصول‌ها، سرویس‌ها و فیلدهای JSON هرگز ترجمه نمی‌شوند.

| فارسی این‌جا | اشاره به | چرا |
| --- | --- | --- |
| میل‌سرور | mail server | همان چیزی که نصب می‌کنی |
| رله | relay / provider | سرویسی که نامه را از طرف تو بیرون می‌فرستد (Brevo، Resend) |
| صندوق / صندوق ورودی | mailbox / inbox | فضای ذخیره‌سازی نامه‌های تو |
| دامنهٔ دسترسی | scope | محدودهٔ کاری که یک توکن اجازه می‌دهد: send، read، status |
| توکن | API token | کلیدی که پروژه‌ات با آن صدا می‌زند |
| صف | queue | نامه‌های زمان‌دار یا دوباره‌تلاش‌شدنی |
| قفل زمان‌دار | lease | مدتی که یک نوبتِ cron یک ردیف را در اختیار دارد تا نامه دو بار ارسال نشود |
| وب‌هوک | webhook | درخواستی که جی‌میل به سرویس تو می‌زند |
| امضا | signature | مقدار HMAC که ثابت می‌کند درخواست واقعاً از جی‌میل آمده |
| کلید خودتوانی | `Idempotency-Key` | سری که اگر تکراری باشد، ارسال دوم انجام نمی‌شود |
| پیوست | attachment | فایل ضمیمهٔ نامه |
| پیش‌نویس | draft | نامهٔ هنوز‌ارسال‌نشده |
| تحویل / وضعیت تحویل | delivery / delivery status | رسیدن، باز شدن، برگشت، یا در انتظار بودن نامه |

نام‌هایی که ترجمه نمی‌شوند: Cloudflare, Workers, D1, R2, Wrangler, Brevo, Resend, DMARC, SPF, DKIM, MX, SMTP, HMAC, webhook, API token, JSON field names.

## قواعد نگارش

- **فرمان‌ها و مسیرها عیناً** از منبع انگلیسی کپی می‌شوند؛ حتی یک گزینه (`--flag`) تغییر یا حذف نمی‌شود، چون خواننده همان فرمان را در ترمینال اجرا می‌کند.
- **عدد و واحد به رقم لاتین** (`5 MiB`, `300`, `*/5 * * * *`)؛ اعداد فارسی فقط در شمارشِ بخش‌های متن (بخش ۰، ۱، ۲…).
- **کلیدهای JSON، نام هدرها و مسیر API** داخل بلوک کد و در متن هم به انگلیسی می‌مانند (`delivery_status`, `Idempotency-Key`, `/api/v1/send`).
- **واژه‌های فنی** (`Worker`, `cron`, `scope`) با معادل فارسی‌شان در پرانتز می‌آیند، ولی در متن‌های بعدی همان واژهٔ انگلیسی کافی است.
- ترجمه **مفهوم را نگه می‌دارد، جمله را نه**: اگر جملهٔ انگلیسی هشداری را می‌گوید، فارسی هم همان هشدار را می‌گوید و چیزی اضافه نمی‌کند.
- هیچ عدد، سقف، یا رفتاری «از خود» نوشته نمی‌شود؛ هر ادعا باید در منبع انگلیسی یا در کد وجود داشته باشد.

## یک نگاه کلی به سیستم

جی‌میل روی سه تکهٔ رایگانِ کلودفلر می‌دود: یک Worker که هم صندوق را سرو می‌کند و هم API را، یک پایگاه دادهٔ D1 برای نامه‌ها و تنظیمات، و یک رابط کاربری که روی همان Worker سرو می‌شود. دریافت نامه از طریق Email Routing انجام می‌شود (رایگان، سقف حدود ۵ MiB برای هر نامه). ارسال از طریق رله‌های رایگانِ بیرونی است، چون کلودفلر در لایهٔ رایگان اجازهٔ ارسال SMTP نمی‌دهد؛ اگر سهمیهٔ روز یک رله پر شود، نامه در صف می‌ماند و با رلهٔ بعدی یا روز بعد ارسال می‌شود، نه اینکه دور ریخته شود.

پروژه‌های تو با `/api/v1/*` به این میل‌سرور وصل می‌شوند: یک توکن با دامنهٔ دسترسی، یک درخواست JSON، و در صورت تمایل یک وب‌هوک برای خبرِ وضعیت تحویل. جزئیات در [مرجع API](API.md) و نمونه‌های آماده در [وصل کردن پروژه‌ها](INTEGRATIONS.md).
